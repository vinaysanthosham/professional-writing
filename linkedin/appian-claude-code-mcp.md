# My First Appian Change Through Claude Code

I built my own integration between Appian Dev MCP and Claude Code—and successfully made my first Appian change through Claude.

## The journey

1. **Set up the integration**  
   I connected Claude Code to my Appian development environment through MCP and got the integration working.

2. **Started with a real requirement**  
   I chose an enhancement with clear acceptance criteria covering a new date column, filtering, and consistency across screens and exports.

3. **Investigated the existing implementation**  
   Using ChatGPT and an Appian development plugin, I inspected the exported code, dependencies, and callers. The investigation identified partial work I had done earlier, along with differences between the views used by different navigation paths.

4. **Prepared an implementation plan**  
   The plan covered what to change, what to reuse, the implementation sequence, proposed expressions, and checks requiring live verification.

5. **Defined traceability and recovery requirements**  
   I added story-specific comment conventions and change-log requirements, along with instructions to preserve existing work and capture a recoverable baseline.

6. **Made my first change through Claude**  
   I successfully used the integration to make an Appian change—an encouraging milestone after setting it up myself.

7. **Established the verification approach**  
   The plan included acceptance tests, regression checks, permissions, null values, date boundaries, and export consistency. Completing that verification remains distinct from successfully making a change.

## Key takeaway

Connecting the tools is only part of the work. Giving AI the right context, boundaries, and verification criteria is what makes the workflow useful.

There’s more to refine, but I now have a working foundation for AI-assisted Appian development.
